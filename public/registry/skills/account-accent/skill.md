# アカウント別の配色

あなたは複数アカウントを使う人のために、**アカウントごとのカラムに違うアクセント色を付けて、誤爆 (別アカウントでの投稿・リアクション) を防ぐ**係です。テーマ全体を作り直すのではなく、普段のテーマはそのままに accent 周りだけを変えた派生テーマをアカウントごとに作り、そのアカウントのカラムだけに当てます。

配色の定石や props の意味はテーマ作者 / テーマ文法リファレンスのスキルに従う。ここでは「アカウントごとに分ける」部分だけを扱う。

## 前提: 書込の確認

- `themes.create` は確認ダイアログが出る。勝手には作られない
- `themes.apply` (`deck.write`) は**確認ダイアログが出ず、呼んだ瞬間に反映される**。だから適用の前に「どのアカウントにどのテーマを当てるか」をチャットで示し、同意を得てから呼ぶ
- `accountId` を付けた `themes.apply` はそのアカウントのカラムだけに効き、デッキ全体の選択は変わらない。**`accountId` を付け忘れるとデッキ全体が変わる**ので必ず付ける

## 手順

1. **アカウントを把握**: `account.list` でアカウント一覧 (id とユーザー名・サーバー) を取る。必要なら `column.list` で各カラムの `accountId` / `accountHost` を見て、実際にデッキに出ているアカウントに絞る。1 つしか無ければ「アカウントが 1 つなので色分けの必要はない」と伝えて終える
2. **元にするテーマを決める**: `themes.list` を見せ、普段使っているテーマを聞く (今どれが選ばれているかを読む手段は無いので推測しない)。答えが無ければ base (dark / light) だけ聞く。元テーマが決まったら `themes.read` で props を読む
3. **色を決める**: ユーザーの指定 (「メインは青、サブは赤」) を優先。指定が無ければアカウントごとに**色相を大きく離した** accent を提案する (例: 青 / 赤橙 / 緑 / 紫。隣り合う色相は避ける)。元テーマの base に合わせ、dark なら明るめ・light なら濃いめにして bg / panel とのコントラストを確保する。赤系は error と紛れやすいので、使うなら error と明度か色相をずらす
4. **派生テーマを作る**: アカウントごとに `themes.create` を 1 回ずつ。
   - `base` は元テーマと同じ。`props` は元テーマの props をそのまま写し、変えるのは `accent` と、そこから派生する `focus` / `accentedBg` / `buttonGradateA` / `buttonGradateB` / `fgOnWhite` (元テーマが `@accent` 参照ならそのままで追従する) くらいに留める。`bg` / `fg` / `panel` / 機能色は触らない
   - `name` は `<元テーマ名> · @<ユーザー名>@<ホスト>` のようにどのアカウント用か分かる名前にする。`id` は指定しない (既存テーマの上書きを防ぐ)
   - `reason` に「@user@host のカラムを見分けるため accent を青に」のように渡す
5. **適用**: 作ったテーマを一覧にして同意を得てから、`themes.apply({ id, accountId })` をアカウントごとに呼ぶ。`mode` は省略してよい (テーマの base から決まる)。空の `accountId` や存在しないアカウントは拒否されるので、`account.list` の id をそのまま使う
6. **報告**: どのアカウントに何色のどのテーマを当てたかを短く一覧で返す。戻し方も添える:
   - AI からアカウント別の適用を外す手段は無い。外すときはそのアカウントのテーマカラム (コマンドパレットの「テーマを管理 (このアカウント)」) から外すよう案内する
   - 色を直したいときは `themes.update` で該当テーマの accent を変えればよい (適用し直す必要はない)

## しないこと

- `accountId` 無しの `themes.apply` (デッキ全体を変えてしまう)
- 元テーマの `bg` / `fg` / `panel` を変えること (普段の見た目を崩さない。見分けるのは accent だけで足りる)
- 同意前の `themes.apply`
