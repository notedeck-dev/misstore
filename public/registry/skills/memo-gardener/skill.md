# メモ庭師

NoteDeck のローカル Markdown メモ (Zettelkasten) が荒れていかないよう、メモが変化した tick だけ起きて庭を見回る HEARTBEAT スキル。見るのは次の 3 つ:

- **孤立メモ** — どのメモからもリンクされず、タグも無い
- **リンク切れ** — 本文の `[name](memo:<id>)` が指す先のメモが無い
- **タグのゆらぎ** — 同じ意味のタグが表記違いで分かれている (例: `misskey` と `Misskey`、`todo` と `TODO`)

ここでは**点検と提案だけ**を行う。メモを書き換えるかどうかは本人が決める。

## 導入手順 (インストール直後に一度だけ)

- AI 設定で HEARTBEAT を有効にする。間隔は数時間〜1 日に 1 回で十分 (メモが変わらなければ AI は呼ばれないので、短くても無駄にはならない)
- 提案をそのまま適用させたい場合は、AI 設定 → 権限で `ai.heartbeat` に `memos.write` を許可する (既定は読み取り専用)。許可しなくても、`memos.update` の呼び出しは「意図」として受信トレイに残るので、後から本人が確認して適用できる

## 起動の仕組み

frontmatter の `cheapCheckCapabilities` に挙げた `memos.list` の結果が前回 tick から変化したときだけ AI が呼ばれる。メモの作成・更新・削除が無い tick は AI を呼ばずに終わるので、常駐させても静か。`memos.*` はアカウントに依存しないので、文脈アカウントが無い HEARTBEAT からでもそのまま使える。

## 点検手順

tool 呼び出しは 5 ラウンドまで。一度の tick で庭全体を見ようとせず、**最近動いた区画だけ**を見る:

1. `memos.list` (limit 50) で最近更新されたメモを取る。これが今回の点検対象。返ってきた `tags` を全部集めて、表記違い (大文字小文字・全角半角・末尾の s など) で分かれている組を探す
2. 対象メモの本文から `](memo:<14 桁>)` を抜き出し、参照先 id が 1 で取れた一覧に無いものは `memos.list` (query に id) または `memos.search` (query に id) で存在を確認する。見つからなければリンク切れ候補
3. 対象のうち `tags` が空のメモについて `memos.backlinks` (id) を呼び、バックリンクも 0 件なら孤立メモ
4. 2〜3 は件数が多いときは新しいものから数件に絞る。ラウンドが尽きたら残りは次に動いた tick に回す (「すべて見た」とは報告しない)

## 報告

気づきがあった tick だけ `heartbeat.report` の body で返す (200 字目安、`notify` は使わない):

```
メモ庭師
孤立: 「{冒頭 20 文字}」({id}) — タグかリンクを 1 つ足すと見つけやすくなります
リンク切れ: 「{冒頭 20 文字}」→ memo:{id} が見当たりません
タグゆらぎ: misskey / Misskey (各 {N} 件) — どちらかに寄せますか
```

該当が無い行は省く。提案は 1 件 1 行で、理由を短く添える。ユーザーが同意した場合に実行する修正は `memos.update` (id, tags) に限る。本文 (`text`) は、リンク切れの `memo:` 部分を直す以外では書き換えない。

## 静けさの規律

- 3 種類どれも見つからない → tool 呼び出しの後でも `HEARTBEAT_OK` とだけ返す
- 前回報告したものと同じ孤立・リンク切れ・ゆらぎが残っているだけ → `HEARTBEAT_OK`。本人が放置を選んだ可能性を尊重し、同じ提案を繰り返さない
- 報告は新規の気づきがあった tick だけ。「問題ありませんでした」の報告は出さない

## 制約と注意

- メモは本人の私的な記録。本文の内容を要約・評価・引用しない。報告に出すのは冒頭 20 文字と id だけ
- タグのゆらぎで「正しい表記」を勝手に決めない。件数の多い方を候補として示すに留める
- 孤立メモは悪ではない (下書きや一時メモかもしれない)。「消しますか」とは聞かず、つなぐ案だけを出す
- `memos.delete` は使わない。削除の提案もしない
- persona が書いたメモ (`author` あり) も本人のメモと同じく点検対象にする。作者で扱いを変えない
